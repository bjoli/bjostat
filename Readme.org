* bjostat — tables of data for Bjolang

A table is a set of named columns in Apache Arrow's layout. Its schema is
known when the program runs: a table read from a file has the columns that
the file has. A column is taken out by name and type, and the type is checked
once, there. After that the column is typed, and a loop over its values is a
loop over a span.

#+BEGIN_SRC scheme
(import (bjostat table))

(def (Ok t) (read-arrow "sales.arrow") :propagate)
(println (table->string t))

(def (Ok price) (doubles t "price") :propagate)   ; (Column double), or an Err
(column-sum price)                               ; vectorized; nulls are skipped
(column-values price)                            ; the values, as a (RoSpan double)
#+END_SRC

A misspelt column, or a column of another type, is an ~Err~ that says what
the table has:

#+BEGIN_SRC text
the table has no column 'pricee'. Its columns are: region, price, qty, rating.
'qty' is a column of long, not of double.
#+END_SRC

A ~Table~ is Arrow's ~RecordBatch~, and a ~(Column %a)~ is Arrow's
~PrimitiveArray<T>~. So a table goes to and from other .NET Arrow code without
a copy.

** The module (bjostat table)

| Function | What it does |
|----------+--------------|
| ~(table-names t)~, ~(table-schema t)~, ~(column-type t name)~ | The schema: names, and each column's ~ColumnType~ |
| ~(table-row-count t)~, ~(table-column-count t)~ | The size |
| ~(doubles t name)~, ~floats~, ~longs~, ~ints~, ~strings~ | A column, typed, or an ~Err~ |
| ~(column-values c)~ | The values, as a ~(RoSpan %a)~, in place |
| ~(column-ref c i)~, ~(string-column-ref c i)~ | One value, or ~None~ at a null |
| ~(column-valid? c i)~, ~(column-null-count c)~, ~(column-length c)~ | The nulls |
| ~(column-sum c)~, ~column-mean~, ~column-min~, ~column-max~, ~column-count~ | Aggregates, with the nulls skipped |
| ~(array->column a [#:valid v])~ | A column of a copy of the array; a null at each ~#f~ of ~v~ |
| ~(array->string-column a [#:valid v])~ | The same, of strings |
| ~(named name c)~, ~(named-strings name c)~, ~(make-table cols)~ | A table of columns |
| ~(named-any name c)~ | The same, for an Arrow column of any type |
| ~(table-select t names)~, ~(table-slice t #:from #:to)~ | Part of a table, without a copy |
| ~(read-arrow path)~, ~(write-arrow t path)~ | Arrow IPC files |
| ~(table->string t #:rows 10 #:digits 1)~ | The names, the types and the first rows, as text; ~#:digits~ rounds the doubles |

*Nulls.* Arrow keeps a value at a null too, and that value is unspecified.
~column-ref~ answers ~None~ there, and the aggregates skip the nulls. A loop
over ~column-values~ reads ~column-valid?~ when ~column-null-count~ is not 0.

*Speed.* Without nulls, ~column-sum~, ~column-min~ and ~column-max~ go to
.NET's ~TensorPrimitives~, which is vectorized. A loop of your own over
~column-values~ is a loop over a span, as fast as one over an array.

*Types.* A column of ~double~, ~float~, ~long~, ~int~ or ~string~ can be
taken out typed. Every other Arrow type, such as timestamps and booleans, is
~(Other name)~ in the schema: a table holds it, prints it and writes it.

** The module (bjostat csv)

#+BEGIN_SRC scheme
(import (bjostat csv))

(def (Ok t) (read-csv "sales.csv") :propagate)
(def (Ok t) (read-csv "sales.csv" #:types [(Tuple "qty" Int)]) :propagate)
(def (Ok t) (csv->table "a,b\n1,x\n") :propagate)
#+END_SRC

| Function | What it does |
|----------+--------------|
| ~(read-csv path)~ | The table of a CSV file; a file that does not open is an ~Err~ |
| ~(csv->table text)~ | The table of CSV text |

Both take ~#:header?~ (~#t~), ~#:separator~ (~#\,~), ~#:types~ and
~#:guess-rows~ (1000).

*Types.* The first row is the names, unless ~#:header? #f~; then the columns
are ~column-1~, ~column-2~ and so on. The type of a column is guessed from
the first ~#:guess-rows~ rows: ~long~ when every field is an integer,
~double~ when every field is a number, ~string~ otherwise. Integers are
guessed as ~long~, not ~int~, so that a large value later in the file still
fits. ~#:types~ gives the type of a column by name, ~int~ and ~float~ too.

*Nulls.* An empty field is a null, in a column of any type.

*Errors.* A row with too many or too few fields, and a field that is not of
its column's type, are an ~Err~ with the line. A column guessed as ~long~
that meets a decimal after the guess becomes a column of ~double~ instead.
A number is in the plain form: no white space, no thousands separators, ~.~
as the decimal point.

*Speed.* The rows are read by ~(text csv)~, one at a time. A field becomes a
number from its UTF-8 bytes, and a string is kept as its bytes. A file of
1 000 000 rows and five columns, 26 MB, reads in about 175 ms, against
95 ms for ~(text csv)~ reading the rows alone (~bench/csv.bjo~).

** An example: some questions to 167 countries

Kaggle's [[https://www.kaggle.com/datasets/manusmitajha/countrydatacsv][Country data]] has, for each country, child mortality, trade and
health spending as % of GDP, income per person, inflation, life expectancy
and children per woman. [[file:examples/countries.bjo][examples/countries.bjo]] asks it a few things:

#+BEGIN_SRC sh
curl -L -o country.zip https://www.kaggle.com/api/v1/datasets/download/manusmitajha/countrydatacsv
unzip country.zip
bjo run examples/countries.bjo Country-data.csv
#+END_SRC

The file is read, and each column's type guessed:

*Does money buy years?* The columns are found first, so a misspelt one is an
~Err~ before any row is read. Then one loop groups the countries by income
and keeps four aggregates, each its own ~:acc~:

#+BEGIN_SRC scheme
(def* ((Ok income) (column-as t "income") :propagate)
      ((Ok life) (column-as t "life_expec") :propagate)
      ((Ok babies) (column-as t "total_fer") :propagate))

(def groups (group-index))
(loop (:for i* income) (:for l* life) (:for b* babies)
      (:when-let (Some i) i*) (:when-let (Some l) l*) (:when-let (Some b) b*)
      (:let g (group-of! groups (bracket (: i long))))
      (:acc n (counting-by groups (Tuple g l)))
      (:acc years (mean-by groups (Tuple g l)))
      (:acc shortest (min-by groups (Tuple g (: l double))))
      (:acc kids (mean-by groups (Tuple g b)))
      => (groups->table groups "income per person"
                        [(Tuple "countries" n) (Tuple "mean life" years)
                         (Tuple "shortest" shortest) (Tuple "children per woman" kids)]))
#+END_SRC

#+BEGIN_SRC text
income per person  countries  mean life  shortest  children per woman
string             int        double     double    double
1. under $2k       27         58.5       32.1      5.3
2. $2k to $10k     57         67.9       46.5      3.2
3. $10k to $30k    51         74.4       54.3      2
4. over $30k       32         79.4       60.9      2
#+END_SRC

It does, with diminishing returns: from the poorest group to the next, nine
years more; to the next, six and a half; to the richest, five. It does not
buy them for everyone, though. The shortest life of the rich is Equatorial
Guinea's, 60.9 years on $33 700 a year: an oil state, where the income per
person is high and shared by few. The shortest of all is Haiti's 32.1, most
likely the figure for 2010, the year of its earthquake.

*Long lives on a small budget*: the countries over 75 years on under $12 000
a year, by a ~:when~ and ~selecting~:

#+BEGIN_SRC scheme
(loop (:for row (range 0 (table-row-count t)))
      (:for i* income) (:for l* life)
      (:when-let (Some i) i*) (:when-let (Some l) l*)
      (:when (and (> l 75.0) (< (: i long) 12000L)))
      (:acc (selecting t row)))
#+END_SRC

Peru and the Maldives, 77.9 years on about $10 000, outlive Russia (69.2
years on $23 100) and Kazakhstan (68.4 on $20 100) by eight and nine years.
Whatever buys those years, it is not only money.

*Prices and trade*, each with a ~folding~ that keeps the most extreme country:

#+BEGIN_SRC text
Prices rise fastest in Nigeria, 104% a year, and fall in Seychelles, -4.21%.

106 of 167 countries import more than they export. The keenest shopper is Liberia, by 73.5 points of GDP.
#+END_SRC

Nearly two countries in three buy more than they sell. The other third,
it seems, is very busy.
