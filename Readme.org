* bjostat — tables of data for Bjolang

A table is a set of named columns in Apache Arrow's layout. Its schema is
known when the program runs: a table read from a file has the columns that
the file has. A column is taken out by name and type, and the type is checked
once, there. After that the column is typed, and a loop over its values is a
loop over a span.

#+BEGIN_SRC scheme
(import (bjostat table))

(def (Ok t) (read-arrow "sales.arrow") :propagate)
(println (table->string t))

(def (Ok price) (doubles t "price") :propagate)   ; (Column double), or an Err
(column-sum price)                               ; vectorized; nulls are skipped
(column-values price)                            ; the values, as a (RoSpan double)
#+END_SRC

A misspelt column, or a column of another type, is an ~Err~ that says what
the table has:

#+BEGIN_SRC text
the table has no column 'pricee'. Its columns are: region, price, qty, rating.
'qty' is a column of long, not of double.
#+END_SRC

A ~Table~ is Arrow's ~RecordBatch~, and a ~(Column %a)~ is Arrow's
~PrimitiveArray<T>~. So a table goes to and from other .NET Arrow code without
a copy.

** The module (bjostat table)

| Function | What it does |
|----------+--------------|
| ~(table-names t)~, ~(table-schema t)~, ~(column-type t name)~ | The schema: names, and each column's ~ColumnType~ |
| ~(table-row-count t)~, ~(table-column-count t)~ | The size |
| ~(doubles t name)~, ~floats~, ~longs~, ~ints~, ~strings~ | A column, typed, or an ~Err~ |
| ~(column-values c)~ | The values, as a ~(RoSpan %a)~, in place |
| ~(column-ref c i)~, ~(string-column-ref c i)~ | One value, or ~None~ at a null |
| ~(column-valid? c i)~, ~(column-null-count c)~, ~(column-length c)~ | The nulls |
| ~(column-sum c)~, ~column-mean~, ~column-min~, ~column-max~, ~column-count~ | Aggregates, with the nulls skipped |
| ~(array->column a [#:valid v])~ | A column of a copy of the array; a null at each ~#f~ of ~v~ |
| ~(array->string-column a [#:valid v])~ | The same, of strings |
| ~(named name c)~, ~(named-strings name c)~, ~(make-table cols)~ | A table of columns |
| ~(named-any name c)~ | The same, for an Arrow column of any type |
| ~(table-select t names)~, ~(table-slice t #:from #:to)~ | Part of a table, without a copy |
| ~(table-sort t [(ascending name) (descending name) …])~ | The rows in the order of the keys, as R's ~order~: stable, nulls last |
| ~(date-cells t name)~, ~datetime-cells~, ~instant-cells~ | A column of dates or timestamps; a loop over it gets ~Date~, ~DateTime~ or ~Instant~ of ~(std datetime)~ |
| ~(inner-join a b keys)~, ~left-join~, ~semi-join~, ~anti-join~ | The rows whose keys are equal, as dplyr's joins: left order, two nulls equal, ~.x~ and ~.y~ on shared names |
| ~(table-distinct t #:by keys)~                                 | The first row of each distinct key, all columns; with no ~#:by~, rows that are not there twice |
| ~(table-append [t …])~                                         | The rows of the tables one after the other, columns by name, nulls where a table has no column, as ~bind_rows~ |
| ~(pivot-longer t cols #:names-to n #:values-to v)~             | Columns to rows, as tidyr's ~pivot_longer~ |
| ~(pivot-wider t #:names-from n #:values-from v)~               | Rows to columns, as tidyr's ~pivot_wider~: a null where no row gives a cell |
| ~(table-count t keys #:name "n")~                             | A row for each distinct key and its number of rows, as dplyr's ~count~ |
| ~(table-crosstab t row-key col-key)~                           | R's ~table(x, y)~: a row for each value of one key, a column of counts for each of the other |
| ~(table-categorize t name #:levels ls)~                        | The column a category; levels sorted, or those given, a string not in them an ~Err~ |
| ~(category-levels t name)~, ~(category-codes t name)~          | A category's levels in order, and its codes as ~(Cells int)~ |
| ~(read-arrow path)~, ~(write-arrow t path)~ | Arrow IPC files |
| ~(table->string t #:rows 10 #:digits 1)~ | The names, the types and the first rows, as text; ~#:digits~ rounds the doubles |

*Nulls.* Arrow keeps a value at a null too, and that value is unspecified.
~column-ref~ answers ~None~ there, and the aggregates skip the nulls. A loop
over ~column-values~ reads ~column-valid?~ when ~column-null-count~ is not 0.

*Speed.* Without nulls, ~column-sum~, ~column-min~ and ~column-max~ go to
.NET's ~TensorPrimitives~, which is vectorized. A loop of your own over
~column-values~ is a loop over a span, as fast as one over an array.

*Types.* A column of ~double~, ~float~, ~long~, ~int~ or ~string~ can be
taken out typed. A column of dates holds days since 1970-01-01, and one of
timestamps microseconds since 1970-01-01T00:00, as in Arrow and Polars; its
cells are ~Date~, ~DateTime~ (no time zone) or ~Instant~ (a time zone) of
~(std datetime)~, made with ~unix-days->date~ and
~unix-microseconds->instant~. A column of ~bool~ is a bit for each value;
its cells are ~bool~. A ~category~ is a column of strings from a small set, as
R's factor: Arrow's dictionary of ~int~ codes and ~string~ levels. Its cells
are strings, and its codes are cells of ~int~. A group-by, a sort or a join
on a category works on the codes. Every other Arrow type is ~(Other name)~ in
the schema: a table holds it, prints it and writes it.

** The module (bjostat csv)

#+BEGIN_SRC scheme
(import (bjostat csv))

(def (Ok t) (read-csv "sales.csv") :propagate)
(def (Ok t) (read-csv "sales.csv" #:types [(Tuple "qty" Int)]) :propagate)
(def (Ok t) (csv->table "a,b\n1,x\n") :propagate)
#+END_SRC

| Function | What it does |
|----------+--------------|
| ~(read-csv path)~ | The table of a CSV file; a file that does not open is an ~Err~ |
| ~(csv->table text)~ | The table of CSV text |

Both take ~#:header?~ (~#t~), ~#:separator~ (~#\,~), ~#:types~ and
~#:guess-rows~ (1000).

*Types.* The first row is the names, unless ~#:header? #f~; then the columns
are ~column-1~, ~column-2~ and so on. The type of a column is guessed from
the first ~#:guess-rows~ rows: ~long~ when every field is an integer,
~double~ when every field is a number, ~date~ when each is an ISO date
(~2026-10-28~), ~datetime~ when each is an ISO date or date and time
(~2026-10-28T14:05~), ~instant~ when each has a time zone (~Z~ or an
offset), ~bool~ when each is ~true~ or ~false~ (also ~TRUE~ and ~True~),
~string~ otherwise. Integers are
guessed as ~long~, not ~int~, so that a large value later in the file still
fits. ~#:types~ gives the type of a column by name, ~int~ and ~float~ too, and
~Dates~, ~DateTimes~, ~Instants~, ~Bool~ and ~Category~: a category is read
as strings and then made one, with its levels sorted.

*Nulls.* An empty field is a null, in a column of any type.

*Errors.* A row with too many or too few fields, and a field that is not of
its column's type, are an ~Err~ with the line. A column guessed as ~long~
that meets a decimal after the guess becomes a column of ~double~ instead.
A number is in the plain form: no white space, no thousands separators, ~.~
as the decimal point.

*Speed.* The rows are read by ~(text csv)~, one at a time. A field becomes a
number from its UTF-8 bytes, and a string is kept as its bytes. A file of
1 000 000 rows and five columns, 26 MB, reads in about 175 ms, against
95 ms for ~(text csv)~ reading the rows alone (~bench/csv.bjo~).

** An example: some questions to 167 countries

Kaggle's [[https://www.kaggle.com/datasets/manusmitajha/countrydatacsv][Country data]] has, for each country, child mortality, trade and
health spending as % of GDP, income per person, inflation, life expectancy
and children per woman. [[file:examples/countries.bjo][examples/countries.bjo]] asks it a few things:

#+BEGIN_SRC sh
curl -L -o country.zip https://www.kaggle.com/api/v1/datasets/download/manusmitajha/countrydatacsv
unzip country.zip
bjo run examples/countries.bjo Country-data.csv
#+END_SRC

The file is read, and each column's type guessed:

#+BEGIN_SRC text
167 countries, 10 columns, the types guessed:
country      child_mort  exports  health  imports  income  inflation  life_expec  total_fer  gdpp
string       double      double   double  double   long    double     double      double     long
Afghanistan  90.2        10       7.58    44.9     1610    9.44       56.2        5.82       553
Albania      16.6        28       6.55    48.6     9930    4.49       76.3        1.65       4090
Algeria      27.3        38.4     4.17    31.4     12900   16.1       76.5        2.89       4460
… 164 more rows
#+END_SRC

*Does money buy years?* The columns are found first, so a misspelt one is an
~Err~ before any row is read. Then one loop groups the countries by income
and keeps four aggregates, each its own ~:acc~:

#+BEGIN_SRC scheme
(def* ((Ok income) (column-as t "income") :propagate)
      ((Ok life) (column-as t "life_expec") :propagate)
      ((Ok babies) (column-as t "total_fer") :propagate))

(def groups (group-index))
(loop (:for i* income) (:for l* life) (:for b* babies)
      (:when-let (Some i) i*) (:when-let (Some l) l*) (:when-let (Some b) b*)
      (:let g (group-of! groups (bracket (: i long))))
      (:acc n (counting-by groups (Tuple g l)))
      (:acc years (mean-by groups (Tuple g l)))
      (:acc shortest (min-by groups (Tuple g (: l double))))
      (:acc kids (mean-by groups (Tuple g b)))
      => (groups->table groups "income per person"
                        [(Tuple "countries" n) (Tuple "mean life" years)
                         (Tuple "shortest" shortest) (Tuple "children per woman" kids)]))
#+END_SRC

#+BEGIN_SRC text
income per person  countries  mean life  shortest  children per woman
string             int        double     double    double
1. under $2k       27         58.5       32.1      5.3
2. $2k to $10k     57         67.9       46.5      3.2
3. $10k to $30k    51         74.4       54.3      2
4. over $30k       32         79.4       60.9      2
#+END_SRC

It does, with diminishing returns: from the poorest group to the next, nine
years more; to the next, six and a half; to the richest, five. It does not
buy them for everyone, though. The shortest life of the rich is Equatorial
Guinea's, 60.9 years on $33 700 a year: an oil state, where the income per
person is high and shared by few. The shortest of all is Haiti's 32.1, most
likely the figure for 2010, the year of its earthquake.

*Long lives on a small budget*: the countries over 75 years on under $12 000
a year, by a ~:when~ and ~selecting~:

#+BEGIN_SRC scheme
(loop (:for row (range 0 (table-row-count t)))
      (:for i* income) (:for l* life)
      (:when-let (Some i) i*) (:when-let (Some l) l*)
      (:when (and (> l 75.0) (< (: i long) 12000L)))
      (:acc (selecting t row)))
#+END_SRC

#+BEGIN_SRC text
country                 income  life_expec
string                  long    double
Albania                 9930    76.3
Bosnia and Herzegovina  9720    76.8
Colombia                10900   76.4
Ecuador                 9350    76.7

Maldives                10500   77.9
Peru                    9960    77.9

#+END_SRC

Peru and the Maldives, 77.9 years on about $10 000, outlive Russia (69.2
years on $23 100) and Kazakhstan (68.4 on $20 100) by eight and nine years.
Whatever buys those years, it is not only money.

*Prices and trade*, each with a ~folding~ that keeps the most extreme country:

#+BEGIN_SRC text

#+END_SRC

Nearly two countries in three buy more than they sell. The other third,
it seems, is very busy.

** The macro (bjostat columns)

~columns~ takes several columns of a table at their types in one form, so
that each is named once:

#+BEGIN_SRC scheme
(import (bjostat columns))

(columns t (price double) (qty long) (seen "first seen" date))
;; the same as
(def* ((Ok price) (: (column-as t "price") (Result TableError (Cells double))) :propagate)
      ((Ok qty) (: (column-as t "qty") (Result TableError (Cells long))) :propagate)
      ((Ok seen) (date-cells t "first seen") :propagate))
#+END_SRC

Nothing is guessed: each column has the type written, and a column the
table does not have, or one of another type, is an ~Err~ of the function
around it. The types are ~double~, ~float~, ~long~, ~int~, ~string~,
~bool~, ~date~, ~datetime~ and ~instant~.

** The module (bjostat query)

A query is a ~loop~ over a table's cells, with collectors for its results.
The columns are found first, where a misspelt name is an ~Err~:

#+BEGIN_SRC scheme
(def* ((Ok price) (column-as t "price") :propagate)
      ((Ok qty) (column-as t "qty") :propagate))
(loop (:for row (range 0 (table-row-count t)))
      (:for p* price) (:for q* qty)
      (:when-let (Some p) p*) (:when-let (Some q) q*)
      (:when (> p 250.0))
      (:acc (selecting t row)))
#+END_SRC

| Collector or function | What it makes |
|------------------------+---------------|
| ~(selecting t row)~ | The table of the rows kept |
| ~(column-building x)~, ~(column-building/option o)~ | A column, a null at each ~None~ |
| ~(dates-building o)~, ~datetimes-building~, ~instants-building~ | A column of dates or timestamps of ~(std datetime)~ values, a null at each ~None~ |
| ~(group-of! groups key)~ and ~summing-by~, ~counting-by~, ~min-by~, ~max-by~, ~mean-by~ | Aggregates by group, ~groups->table~ the table of them |
| ~(category-groups t name)~ | The groups of a category's levels, so that a row's code is its group, with no hash |
| ~(grouping c (Tuple key x))~, ~(pairing c d)~ | Any collector by key, ~map->table~ the table |
| ~(table-with t name c)~ | The table with a column more, or one replaced |

The loop is the one way to make a column, a filter or a group. Bjolang is to
make vector code of simple loops (Docs/Vectorisation-design.org in Bjolang),
so that the same loop becomes faster, with no second API for speed.

** The module (bjostat stats)

Statistics are collectors of doubles, so they are loops too. A null is left
out by the loop, where R needs ~na.rm = TRUE~:

#+BEGIN_SRC scheme
(loop (:for p* price) (:when-let (Some p) p*) (:acc (summarizing p)))
;; Some summary: n, min, q1, median, mean, q3, max, sd
(loop (:for p* price) (:for q* qty)
      (:when-let (Some p) p*) (:when-let (Some q) q*)
      (:acc (correlation (Tuple p (cast double q)))))
#+END_SRC

| Collector or function | What it makes |
|------------------------+---------------|
| ~(mean x)~, ~(variance x)~, ~(standard-deviation x)~ | One pass; the variance of a sample, as R's ~var~ and ~sd~ |
| ~(covariance (Tuple x y))~, ~(correlation (Tuple x y))~ | One pass; Pearson's correlation, as R's ~cor~ |
| ~(median x)~, ~(quantile p x)~, ~(quantiles ps x)~ | As R's ~quantile~ by default (type 7) |
| ~(summarizing x)~, ~(summary->string s)~ | R's ~summary~ of numbers, with the count and the standard deviation |
| ~(table-summary t)~ | A table of a row for each column: type, count, nulls, and the summary of numbers |

Each is None of too few values: the mean of none, the variance of fewer than
two. A quantile of values with a NaN is NaN.

** The module (bjostat distributions)

The density, the distribution function, the quantile function and samples
of the normal, t, chi-squared, F, binomial and Poisson distributions, as R's
~dnorm~, ~pnorm~, ~qnorm~, ~rnorm~ and the others. The arguments are in R's
order: the value, then the parameters.

#+BEGIN_SRC scheme
(normal-cdf 1.96)                         ; 0.975, R's pnorm(1.96)
(t-cdf 2.5 10.0 #:lower? #f)              ; P(T > 2.5), R's pt(2.5, 10, lower.tail = FALSE)
(chi-squared-quantile 0.95 3.0)           ; 7.81, R's qchisq(0.95, 3)
(binomial-probability 3L 10L 0.5)         ; 0.117, R's dbinom(3, 10, 0.5)
(normal-sample #:mean 10.0 #:rng (make-random/seed64 42UL))
#+END_SRC

| Distribution | Functions |
|--------------+-----------|
| Normal | ~normal-density~, ~normal-cdf~, ~normal-quantile~, ~normal-sample~, with ~#:mean~ and ~#:sd~ |
| Student's t | ~t-density~, ~t-cdf~, ~t-quantile~, ~t-sample~ |
| Chi-squared | ~chi-squared-density~, ~-cdf~, ~-quantile~, ~-sample~ |
| F | ~f-density~, ~f-cdf~, ~f-quantile~, ~f-sample~ |
| Binomial | ~binomial-probability~, ~-cdf~, ~-quantile~, ~-sample~ |
| Poisson | ~poisson-probability~, ~-cdf~, ~-quantile~, ~-sample~ |
| Others | ~uniform-sample~, ~gamma-sample~, ~log-gamma~ |

A distribution function or a quantile function takes ~#:lower?~ (~#t~);
with ~#f~ it is of the upper tail, which keeps the digits of a small
p-value. A continuous distribution with a parameter out of its range gives
NaN, as R does; a binomial or Poisson quantile or sample panics. A sample
takes ~#:rng~, a ~RandomSource~ of ~(std random)~: one made with a seed
gives the same samples each run.

*Accuracy.* Checked against mpmath at 50 digits on a grid of values and
parameters: a relative error below 1e-12 almost everywhere, also of p-values
of 1e-130 and quantiles of 1e-300. Above 4e5 degrees of freedom the t is
R's corrected normal, of about 10 digits.

** The module (bjostat models)

A linear model of least squares, as R's ~lm~, is a collector too: each row
gives the response and its predictors.

#+BEGIN_SRC scheme
;; R's lm(dist ~ speed)
(loop (:for s* speed) (:for d* dist) (:when-let (Some s) s*) (:when-let (Some d) d*)
      (:acc (simple-linear-model "speed" (Tuple d s))))
;; R's lm(price ~ area + rooms)
(loop (:for p* price) (:for a* area) (:for r* rooms)
      (:when-let (Some p) p*) (:when-let (Some a) a*) (:when-let (Some r) r*)
      (:acc (linear-model ["area" "rooms"] (Tuple p [a (cast double r)]))))
#+END_SRC

| Collector or function | What it makes |
|------------------------+---------------|
| ~(linear-model names (Tuple y xs))~ | A ~LinearModel~ with an intercept, or a ~ModelError~ |
| ~(linear-model/origin names (Tuple y xs))~ | The same with no intercept, as R's ~- 1~ |
| ~(simple-linear-model name (Tuple y x))~ | The model of one predictor |
| ~(model->string m)~ | The model as R's ~summary.lm~ prints it |
| ~(model->table m)~ | The coefficients as a table, as broom's ~tidy~ |
| ~(model-predict m xs)~ | The response the model gives |

Logistic and Poisson regression, R's ~glm~ of the ~binomial~ and ~poisson~
families, are collectors of the same rows:

| Collector or function | What it makes |
|------------------------+---------------|
| ~(logistic-model names (Tuple y xs))~ | A ~GeneralizedModel~ of a response from 0 to 1, with the logit |
| ~(poisson-model names (Tuple y xs))~ | The same of counts, with the log |
| ~(glm->string m)~, ~(glm->table m)~ | As R's ~summary.glm~, and as broom's ~tidy~ |
| ~(glm-predict m xs)~ | The mean response: a probability, or a mean count |

A ~GeneralizedModel~ has the estimates, standard errors, z values and
p-values, the deviance and the null deviance, the AIC, and whether the fit
converged. It is fitted by iteratively reweighted least squares, as R's, so
its collector keeps the rows.

A model keeps no rows, so what it says of each row comes from a second loop
over them: ~(model-residual m y xs)~, ~(model-leverage m xs)~ (R's
~hatvalues~), ~(model-standardized-residual m y xs)~ (~rstandard~), and
~(model-mean-interval m xs 0.95)~ and ~(model-prediction-interval m xs
0.95)~, R's ~predict~ with ~interval = "confidence"~ and ~"prediction"~;
~glm-residual~ of a generalized model.

#+BEGIN_SRC scheme
(loop (:for s* speed) (:for d* dist) (:when-let (Some s) s*) (:when-let (Some d) d*)
      (:acc (column-building (model-residual m d [s]))))
#+END_SRC

~(with-categories linear-model ["area"] [(Tuple "region" levels)] (Tuple y [a] [code]))~
is a model of a number and a category: each category, its name and levels,
is a predictor of its indicators, with R's names, and each element has the
category's code. It takes ~linear-model~, ~linear-model/origin~,
~logistic-model~ or ~poisson-model~.

~(model-intervals m 0.95)~ is R's ~confint~, and ~(glm-intervals m 0.95)~ its
~confint.default~, of Wald. A category is a predictor as R makes it, a 0 or
1 for each level but the first: ~(indicators (vec-length levels) code)~ of
its code, with the names ~(indicator-names "region" levels)~.

A ~LinearModel~ has the terms, the estimates, standard errors, t values and
p-values, sigma, the degrees of freedom, R², adjusted R², and the F
statistic and its p-value, as ~summary.lm~. The rows are not kept: each one
goes into a QR decomposition by Givens rotations, so the memory is that of
p² numbers, and the fit is as stable as R's QR. A model with no more rows
than coefficients, or a predictor that is a linear combination of the
others, is an ~Err~ where R gives NA.

** The module (bjostat hypothesis)

t-tests are collectors, and the chi-squared test takes a table that
~table-crosstab~ makes, as R's ~t.test~ and ~chisq.test~:

| Collector or function | What it tests |
|------------------------+---------------|
| ~(one-sample-t-test mu x)~ | Is the mean ~mu~? |
| ~(paired-t-test mu (Tuple x y))~ | Is the mean of x - y ~mu~? |
| ~(welch-t-test mu (Tuple first? x))~ | Is the difference of the means of two samples ~mu~? R's default |
| ~(pooled-t-test mu (Tuple first? x))~ | The same, with equal variances, R's ~var.equal = TRUE~ |
| ~(t-test-interval r level)~, ~(t-test->string r)~ | The confidence interval, and the test as text |
| ~(chi-squared-test t #:correct? #t)~ | Are the rows and the columns of the counts independent? Yates's correction of a 2 × 2 table, as R |

A ~TTest~ has the p-value of the two-sided alternative and ~p-less~ and
~p-greater~ of the one-sided ones. A ~ChiSquaredTest~ has the statistic,
the degrees of freedom, the p-value and the table of expected counts.
